Phase 1:

kind create cluster --config kind-config.yaml

2.Deploy Ingress Controller & Cert-Manager:Apply the Kind-tailored NGINX Ingress controller and cert-manager:Bash# 1. Install Ingress Controller
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml

Force Ingress Controller onto primary control-plane node (where 8080/8443 are mapped)
kubectl patch deployment ingress-nginx-controller -n ingress-nginx \
  --type='json' -p='[
    {"op": "replace", "path": "/spec/template/spec/nodeSelector", "value": {"kubernetes.io/hostname": "kind-control-plane"}},
    {"op": "add", "path": "/spec/template/spec/tolerations", "value": [{"key": "node-role.kubernetes.io/control-plane", "operator": "Exists", "effect": "NoSchedule"}]}
  ]'

3. Install cert-manager
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.1/cert-manager.yaml

Deploy Kustomize Application Stack:Wait 30 seconds for the webhook to initialize, then deploy all applications, policies, HPA, and TLS configurations using Kustomize:Bash# Wait for cert-manager webhook availability

kubectl rollout status deployment/cert-manager-webhook -n cert-manager --timeout=90s

# Deploy entire stack
kubectl apply -f cluster-issuer.yaml
kubectl apply -k k8s-config/


4.Install & Patch Metrics Server:Integrate metrics-server to feed real-time resource data to the HPA and Kubernetes Dashboard:Bash

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

kubectl patch deployment metrics-server -n kube-system --type='json' -p='[
  {"op": "add", "path": "/spec/template/spec/containers/0/args/-", "value": "--kubelet-insecure-tls"}
]'


Dashboard


Step 1: Install the Kubernetes Dashboard
Apply the official Kubernetes Dashboard manifest:

Bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/dashboard/v2.7.0/aio/deploy/recommended.yaml
Wait until the dashboard pod is running:

Bash
kubectl rollout status deployment/kubernetes-dashboard -n kubernetes-dashboard --timeout=90s

Step 2: Apply dashboard-admin.yaml & Generate Token
Now that the kubernetes-dashboard namespace exists, re-run your commands:

Bash
kubectl apply -f dashboard-admin.yaml
kubectl create token admin-user -n kubernetes-dashboard
(Copy the long token generated by the last command).

Step 3: Access the Dashboard
Start the local proxy:

Bash
kubectl proxy
Navigate to the dashboard in your browser:

Plaintext
http://localhost:8001/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/
Paste your bearer token at the sign-in prompt. Once logged in, all cluster metrics, pod workloads, and CPU/memory utilization graphs will be fully populated.
